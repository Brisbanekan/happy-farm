# Farmstead 農莊

由 Claude 全權設計實作的等角農場遊戲。素材全部以程式繪製（`tools/gen_assets.py`，PIL）。

**線上試玩**：https://brisbanekan.github.io/happy-farm/farmstead/

---

## 為什麼這樣蓋（設計決策）

這個專案是針對舊版 happy-farm 踩過的坑重新設計的。核心差異在三點。

### 1. 世界與 UI 徹底分層

舊版把世界物件（建築、作物）和 UI 按鈕放在同一個 DOM 樹裡，用 CSS transform 一起縮放，所以「農場放大」和「按鈕大小」互相牽動，一改就顧此失彼。

這裡分成兩層：

- **世界層**＝canvas，只受 `camera{x, y, zoom}` 影響
- **UI 層**＝DOM，完全不受 camera 影響，尺寸由 `--u` 單位推導

`--u` 的計算：`u = clamp(0.78, min(vw/640, vh/360), 1.6)`。以 640×360 為設計基準等比縮放，所以桌機、手機預覽、真機的視覺比例一致——不會再有「預覽剛好、真機太小」的問題。

實測：780×360 手機 → u=1.0 → 主按鈕 56px；844×390 → u=1.08 → 60px。都在觸控舒適區（44px 是下限，不是目標）。

### 2. 等角格線，不是自由擺放

所有物件用格座標 `(col, row)`，渲染時才換算螢幕位置：

```
screenX = (col - row) * TILE_W/2
screenY = (col + row) * TILE_H/2
```

深度排序直接用 `col + row`。點擊判定是**反矩陣運算**（`worldToGrid`），不是逐像素 alpha 判定——所以不需要 clip-path 描圖、不會有透明角落攔截點擊的問題。舊版花大量時間處理的那類坑，在這個座標系下不存在。

### 3. 狀態單一來源

`State.data` 是唯一狀態，所有變更走 `Act.*` 這組 action，存檔就是序列化整個物件。時間一律存**絕對時間戳**（`plantedAt`），所以離線續算天然正確，不需補算誤差。

## 玩法設計

**核心循環**：種下 → 等待 → 收成 → 賣錢 → 買更好的種子。第一圈（胡蘿蔔 30 秒）刻意設短，讓新玩家一分鐘內走完一輪、立刻理解遊戲。

**等待期**是農場遊戲的核心，所以：

- 澆水縮短 25% 成長時間 → 給玩家「主動加速」的操作空間
- 離線期間作物持續成長，回來有「歡迎回來」結算 → 收穫感集中
- 批次操作（全種／全澆／全收）→ 田多了以後不必逐格點

**動物**是第二層產出：母雞 90 秒下蛋、乳牛 240 秒產奶，會在牧場自由走動，產物出現時點一下收成。存量上限 12 個，避免離線暴利破壞經濟。

**經濟曲線**：作物售價約為種子成本的 2.2～3 倍，成長時間越長利潤率越高（胡蘿蔔 30 秒賺 12，南瓜 420 秒賺 290）。田地解鎖價格 1.55 倍指數成長，作為金幣的長期出口。

**刻意不做的**：舊版的股市、拉霸這類與農場循環分離的系統。它們會變成「另一個遊戲」稀釋主線。若要加，我會設計成消耗農產品的出口，讓它服務主循環。

## 檔案結構

```
farmstead/
├── index.html          遊戲本體（單檔：State / World / Input / Game / UI）
├── assets/             31 個程式生成的 PNG
└── tools/
    └── gen_assets.py   素材產生器（改參數重跑即可換風格）
```

## 素材生成

```bash
python3 tools/gen_assets.py
```

全部以 PIL 繪製，4× 超取樣後 LANCZOS 縮放取得抗鋸齒邊緣。地磚 128×64（2:1 等角），物件錨點一律**底部中心**（座標＝腳底，深度排序才正確）。

改 `P` 色盤字典就能整體換色；改 `make_*` 函式就能換造型。

## 程式架構

| 區塊 | 職責 |
|---|---|
| `State` | 存檔載入/儲存、版本相容補欄位 |
| `Act` | 所有狀態變更（種植/澆水/收成/買賣/解鎖） |
| `World` | canvas 渲染、camera、座標換算、深度排序 |
| `Input` | 指標事件：拖曳平移、雙指/滾輪縮放、點擊 |
| `Game` | 玩法邏輯、工具模式、智慧互動判定 |
| `UI` | DOM 介面、彈窗、尺度計算 |

**智慧互動**：點田地時依狀態自動決定行為——成熟就收成、有作物且選了澆水就澆水、空地就播種。減少玩家切換工具的次數。

**拖曳門檻** 10px，超過才算平移，否則算點擊——避免點擊被誤判成拖曳。

## 美術素材流程（Canva AI）

素材由 Canva AI 生成後，以 `tools/process_ai_assets.py` 處理成遊戲可用的 PNG。

**流程**：`generate-design`（挑選候選）→ `create-design-from-candidate` → `export-design`（512×512 PNG）
→ 瀏覽器下載到本機 → 腳本去背/裁切/縮放 → `assets/`

**去背的兩個關鍵**：

1. **容差必須極小（tol=2）**。AI 生成的白色物件（母雞白羽 `255,252,246`）與純白背景只差數階，
   容差一寬，泛洪就會從邊緣抗鋸齒像素漏進物件內部，把整片白色主體吃掉。
   採用「從四邊泛洪」而非「全域比色」，物件內部的白色（乳牛白身）才能保留。
2. **AI 會自作主張畫地面陰影**，在綠色草地上會顯成白斑。
   `drop_ground_shadow()` 只掃圖片底部 24%，且只移除「冷灰」像素（`b >= r`），
   暖白色的雞身（`b < r`）不受影響。

**注意**：Canva 免費方案不支援透明背景匯出，因此一律匯出白底再程式去背。

**地磚維持程式生成**：等角地磚必須嚴格對齊 2:1 菱形且四邊無縫，AI 生圖做不到這種精度，
`tile_*.png` 仍由 `tools/gen_assets.py` 產生。

**換素材後記得改 `ASSET_VER`**（index.html），否則瀏覽器會沿用舊圖快取。

## 介面圖示

UI 不使用 emoji——emoji 在各裝置字體不同，風格與遊戲美術不搭。
改為 `SVG` 物件中的內嵌向量圖示，透過 `ic(name, size)` 產生，
HTML 端寫 `<span data-ic="名稱">` 由 `hydrateIcons()` 填入。
canvas 上的鎖頭以 `World.drawLock()` 直接繪製路徑。
