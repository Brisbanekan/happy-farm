# happy-farm v1.5 — 等角 canvas 世界層

本機測試版。**線上的 `happy-farm.html` 完全沒有動到。**

## 怎麼開

直接用瀏覽器開這個資料夾裡的 `happy-farm-iso.html`（雙擊即可）。
素材（`animal/ background/ building/`）已經放在同一層，離線可跑。
Firebase 登入與股市報價需要連網；沒有網路時點「先本機試玩」照樣能玩。

## 這版改了什麼

只動世界層，玩法系統一行都沒改。

| | 改之前 | 改之後 |
|---|---|---|
| 世界 | `#world` 固定 2200×1000 的 DOM 舞台 | 一張 `<canvas>`，每幀重畫 |
| 等角 | `rotate(14deg) scaleY(.5) rotate(45deg)` 假造，子元素反向補正 | `Iso.toWorld / toGrid` 座標換算 |
| 田地 | CSS grid(3 欄) 疊在田地大圖上 | 6×4 格座標，`index = row*6 + col` |
| 深度 | `zFor(y)` + `zTick()` 每幀手動維護 z-index | `col + row` 排序，一個 for 迴圈畫完 |
| 點擊 | `silhouettePolygon` 描圖 + `clip-path` + 逐像素 alpha | 螢幕 → 世界 → 格 → 索引，三行數學 |
| 建築 | CSS 寫死 `left:49px;top:247px` | `PROPS` 陣列，佔哪一格是資料 |
| 動物 | 另一個 DOM 世界、`%` 定位 | 同一套格座標，走到哪深度都對 |
| 牧場 | 獨立場景 `#ranchBg` | 同一座島上的相鄰區域，切換鈕已移除 |
| 縮放 | 改 `#world` 的 transform | 只動 `Camera.zoom` |

## 平坦世界（目前預設）

`FLAT_WORLD = true`：不畫天空與遠山，草地地磚直接鋪滿整個畫面。

做法是把畫面四角反算回格座標，取得可視格範圍再逐格鋪。等角轉換是線性的，
四角的 min/max 就是精確的格座標包圍盒，所以不管怎麼平移縮放都不會露出邊緣。

想回到「有邊界的島 + 遠景幕布」，把 `FLAT_WORLD` 改成 `false` 即可，
`drawBackdrop` / `drawIslandShadow` / `drawIslandEdge` 都還留著。

## 柵欄與可拖範圍

```js
const BASE_ZOOM = 1.2;                                   // 整體視角縮放基準
const FENCE = { c0:-4.5, c1:9.5, r0:-4.5, r1:9.5, ... };  // 14×14 正方形
```

`c1-c0` 與 `r1-r0` 相同（各 14 格）＝格線上的正方形，投影到等角後是正菱形。
這四個數字同時決定柵欄畫在哪、以及鏡頭能拖到哪。

**鏡頭夾取**是「視窗感知」的——`Camera.clamp()` 把視窗半徑（`view.w / 2 / zoom`）算進去，
所以柵欄外面永遠看不到，而且**改 `BASE_ZOOM` 時可拖範圍會自動跟著調整**，不必另外改參數。

| 縮放 | x 可拖範圍 | y 可拖範圍 |
|---|---|---|
| 0.42（最小） | 鎖定 0 | 126.8 ~ 173.2（幾乎鎖定置中） |
| 1.20（預設） | −623 ~ 623 | −175 ~ 475 |
| 3.40（最大） | −851 ~ 851 | −280 ~ 580 |

## 圖層重疊：四個成因

### ★ 地面與物件是兩個獨立的繪製層（根本解）

原本地磚和物件排在**同一個 `col+row` 清單**裡，所以只要地磚圖比理想菱形高一點點，
前一列的地磚就有機會蓋到站在後面的動物。調錨點只能把傷害從 44px 降到 7px，
沒辦法歸零——因為架構上地磚本來就有資格蓋過物件。

改成兩層，地面層整層畫完，物件層才開始：

```js
const grounds = [], items = [];
const addG = (depth, fn) => grounds.push({depth, fn});   // 草地、土地、乾旱染色、hover 框
const add  = (depth, fn) => items.push({depth, fn});     // 作物、建築、動物、柵欄、鎖、浮字

grounds.sort((a,b) => a.depth - b.depth); for (const g of grounds) g.fn();
items  .sort((a,b) => a.depth - b.depth); for (const it of items)  it.fn();
```

田地也跟著拆成 `drawPlotGround()`（土地本身）與 `drawPlotItems()`（作物、進度條、狀態圖示）。

**各層內部仍然依 `col+row` 排序**——物件之間該互相遮擋，前方的柵欄本來就要蓋住後方的動物，
那是要的；地面蓋掉站在上面的東西則永遠不是要的。兩者分開之後，
地磚在物理上不可能蓋到任何物件，不管素材比菱形高出多少。

## 其他三個成因

### 三、素材錨點落在地磚的「前端頂點」而不是「中心」

動物和房子被前方地磚埋掉一截，元凶是這行：

```js
c.drawImage(im, sx - dw/2, sy - dh + TILE_H/2*z, dw, dh);   // ← 舊寫法
```

`+ TILE_H/2` 把素材底邊壓到地磚的**前端頂點**，也就是比地磚中心低 37.5px。
偏偏地磚圖又比理想的 2:1 菱形高一截——`grass.png` 高出 7.1px、`lend.png` 高出 11.5px，
所以前一列的地磚一畫上來，就會從腳下往上蓋掉約 **44px**。放大時更明顯。

改成底邊落在**地磚中心**（拿掉 `+ TILE_H/2`），前方地磚只會蓋到腳邊 7px，
讀起來就是「草長在腳前面」，自然。

需要底邊落在前端頂點的是**有佔地的建築**，這由呼叫端自己加：

```js
w.y += (k + 1) * TILE_H / 2;   // k 格移到佔地最前面那格，再 1 個半格到頂點
```

語意分開之後就不會互相打架：**點狀物件站在格子中心，佔地物件貼齊佔地前緣**。

### 一、素材的透明留白（真的是素材問題）

`house.png` 原本是 1024×722，實際內容只有 854×455——**底部有 142px 的透明留白**，
等於整棟房子浮在接地線上方 45 個世界像素。`dog.png` 更誇張，底部留白 211px。
素材底邊不等於接地線，錨點就是騙人的，遮擋自然全錯。

修法是把這幾張裁到內容邊界，並把 `h` 依高度比例調回去，維持原本的視覺大小：

| 素材 | 原尺寸 | 裁切後 | `h` |
|---|---|---|---|
| `house.png` | 1024×722 | 854×455 | 230 → 145 → 174（再放大 1.2 倍） |
| `factory.png` | 674×402 | 585×366 | 215 → 196 |
| `storage.png` | 453×307 | 453×304 | 200 → 198 |
| `doghouse.png` | 437×406 | 427×397 | 110 → 108 |
| `dog.png` | 923×1152 | 834×941 | 62 → 51 |

其餘動物素材本來就沒有留白，不用動。

### 二、大型建築只用一個點算深度（架構問題）

深度排序是 `col + row`，但一棟兩、三格寬的房子只算一個錨點，
它旁邊、明明在它前面的物件會被判成在後面。

`PROPS` 因此加上 `fw` / `fh`（佔地幾欄 × 幾列，`col/row` 是佔地中心）：

```js
const k = ((fw - 1) + (fh - 1)) / 2;   // 佔地從中心往前延伸幾格
w.y += k * TILE_H / 2;                 // 素材底部對到佔地的前端頂點
add(Iso.depth(pr.col, pr.row) + k, …); // 深度用佔地最前端那一格
```

農舍、倉庫、工廠都是 2×2，狗屋與樹木 1×1。佔地大小與素材寬度要相符——
素材寬度 ÷ 75 就是 `fw + fh` 的合理值，差太多的話宣告的佔地就是假的。

## 佈局編輯模式

網址加上 `?edit=1` 就開啟，例如：

```
happy-farm-iso.html?edit=1
```

- **直接拖曳建築**改 col/row，右側面板即時顯示數值
- **方向鍵微調**（選中物件後）——上下左右對應的是等角的兩個軸，不是螢幕的 xy
- **吸附**可選 0.05 / 0.1 / 0.25 / 0.5 / 1 格，或不吸附
- 選中的物件會用黃線畫出**佔地範圍**（`fw × fh` 每一格），方便對照素材寬度
- **調素材大小**：`h` 有數字框＋滑桿＋±5% 按鈕，快捷鍵 `[` 縮小 / `]` 放大（按住 Shift 為 1%）
- 調大小時會即時算出「畫出來多寬」與**建議的 `fw+fh`**（寬 ÷ 75），跟目前佔地差超過 0.6 會變橘色警告
- 面板也能改 `fw`/`fh`（佔地），以及 `PEN` 和 `FENCE` 的四個邊界
- 改 `FENCE` 時鏡頭範圍會自動重算，不然會拖不到新邊界
- **📋 複製 JS** 把整段 `PROPS` / `DOG_AT` / `PEN` / `FENCE` 複製到剪貼簿，貼回原始碼即可

編輯模式下拖曳建築不會平移世界；拖曳空地照樣平移。狗屋與看門狗平常不在命中清單裡
（遊戲中點牠們應該落到底下的地磚），只有 `?edit=1` 時才加進去讓你拖。

**改動不會存檔**——重新整理就回到原始碼裡的數值。這是刻意的：編輯器只負責量座標，
真正的來源永遠是原始碼。

原圖是黑底不透明，去背用**從邊界泛洪**的方式：只有「連得到畫面邊緣的暗像素」才變透明，
物件內部的深色描邊因此完整保留（直接用亮度門檻會把描邊一起吃掉）。

**畫法**：素材本身已經畫成等角斜的，所以不需要剪切。只要把圖上量出來的
**兩個柱底錨點**（`ax0/ay0` 左端、`ax1/ay1` 右端）對到那一段的兩個世界端點：

```js
const a = sdx / pdx;                 // 水平縮放：由段長推出
const d = Math.abs(a);               // 垂直縮放：等比，柱子不會被壓扁
const b = (sdy - d * pdy) / pdx;     // 微剪切：吸收素材角度與理論等角的誤差
c.transform(a, b, 0, d, sa.x - a*ax0, sa.y - d*ay0 - b*ax0);
```

第三行是關鍵：Gemini 畫的角度是 24.6°、理論等角是 26.57°，差了 8%。
用一點點剪切把誤差吸掉，段與段就會嚴絲合縫地接上，而不是越接越歪。
**換素材時要重新量錨點**（量法：取不透明像素在最左/最右邊帶的最低點）。

門放在前緣，位置由 `FENCE.gateCol` 決定；設成 `null` 就整圈都是直段。

## 牧場圍籬與動物範圍

牧場用第二款素材（開放式橫桿白圍籬，比外圍柵欄矮，動物才看得到）：
`building/fence_pen_col.png`、`fence_pen_row.png`，畫法與錨點機制跟外圍柵欄完全相同。

```js
const PEN = { c0:-0.5, c1:5.5, r0:4.5, r1:8.5, IN:0.42, gapCol:null, ... };   // 6 欄 × 4 列
```

- `c0~c1 / r0~r1` 是**圍籬線**的位置；寬度剛好對齊上方的田地（同樣 6 格）
- `IN` 是動物與圍籬的內縮距離 → 實際活動範圍是 col −0.08~5.08、row 4.92~8.08
- `PEN.clamp()` 每一幀都夾一次，所以舊存檔裡座標亂掉的動物會自己走回圈內
- `PEN.spawn()` 也用內縮後的範圍，新買的動物不會生在欄杆上
- `gapCol` 是前緣留的出入口，目前 `null`＝整圈封閉；填 0~5 就會在前緣開一格

驗證：8 隻動物起始座標故意放到圍籬外，跑 4000 幀後越界次數 0、最大越界量 0。

### 走路邏輯

移植初期照搬了「每隔 2.2~5.2 秒重挑一個隨機目標」的寫法，結果動物會卡住。三個原因：

1. **抵達目標後只能原地等計時器**，最長站 5 秒不動
2. **目標超出圍籬時是「夾到邊界」**，於是大量目標堆在欄杆上，動物一直貼著圍籬走
3. **位移是每幀固定 0.009 格**，不是乘 `dt`，所以更新率一變速度就跑掉

改成沿用 v1 `nextTarget` 的手感：

- `pickTarget()` 從現在位置往附近走一小步（0.8~3 格），**出界就換個角度重試**，不夾邊界
- **抵達才重挑**，並排一段 0.6~2.5 秒的吃草停頓
- 速度以「格/秒 × dt」計；每隻 `a.sp` 有 0.55~0.95 的隨機差異，整群不會同步
- `dt` 上限 0.05 秒——分頁切回前景時 `now` 會暴增，不夾住動物會瞬間傳送

實測 60 秒：每隻移動 25~35 格、平均 0.52 格/秒、最長靜止 2.5 秒（就是設計上的吃草停頓）、越界 0 次。

### 舊存檔的座標會讓動物全部擠在同一角

牧場搬過家（從田地右邊移到下方、尺寸也改過）之後，存檔裡的 `gc/gr` 和 `tc/tr`
都還是舊牧場的座標。當時只有 `PEN.clamp()` 一道防線，於是：

1. 所有動物的位置被夾到新牧場**同一個角落**
2. 目標也在圍籬外，動物朝它走 → 每幀又被夾回角落 → 距離永遠不會小於 0.06
3. 因為「抵達才重挑目標」，這個條件永遠不成立 → **永久卡死**

修法是加一道 `PEN.has()` 驗證，位置與目標都要驗：

```js
if (!PEN.has(a.gc, a.gr)){ 重新配位；順便作廢舊目標 }
if (!PEN.has(a.tc, a.tr)){ 重挑目標 }
```

再加一道保險：實際位移小於預期一半就換目標。位置與目標都保證在圍籬內之後，
兩點之間的直線一定也在圍籬內，clamp 根本不會被觸發。

實測（8 隻用舊牧場座標開場）：45 秒後散開在整個牧場，任兩隻最近距離 0.42 格，
每隻移動 13~21 格。

每一段柵欄也走 `col + row` 深度排序，所以前方柵欄會蓋住後方物件、後方柵欄被前方物件蓋住。
畫面外的段會被剔除（預設視角每幀只畫 12 段，不是全部 54 段）。

## 程式結構

新的世界層是單一區塊，在 `/* ============ start ============ */` 之前：

```
Iso        等角座標系（TILE_W=150, TILE_H=75，對齊 lend.png / grass.png 的尺寸）
Camera     x / y / zoom，只影響世界層
FIELD_*    田地版面：6 欄 × 4 列 → plotGrid(i) / gridToPlotIndex(col,row)
PEN        牧場區域（格座標），動物在裡面走動
ISLAND     農場島邊界（橢圓判定），島外是遠景
PROPS      建築與裝飾：{key, img, col, row, h, act}
World      canvas 渲染 + 命中測試
Input      pointer 事件：拖曳平移、滾輪/雙指縮放、點擊派發
相容層     覆蓋 v1 舊世界層的同名函式（見下）
```

被覆蓋成 no-op 或 camera 版的舊函式：
`buildWorld / renderGrid / renderPen / clearPen / zFor / startZTick / zTick /
scheduleWalk / walkAnimal / walkDog / initBldHit / initEditor / initFabDrag /
updateFade / applyWorld / clampPan / calcWorldScale / computeBaseScale /
coverScale / setZoom / pinchZoom / zoomIn / zoomOut / initPan / centerField /
setScene / balloonFrame`

JS 的函式宣告會提升且後宣告者勝出，所以玩法系統呼叫這些名字時拿到的都是新版本。
